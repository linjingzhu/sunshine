아이디어를 검증된 결과로 만드는
AI Engineering Manager 운영체계

이 패키지는 별도의 오케스트레이터 프로그램을 만드는 것이 아니라, 저장소의 Markdown 지침을 통해 Claude Code와 Codex의 메인 세션이 Manager가 되고 필요한 Worker/Reviewer를 조직하도록 설계되어 있습니다.

동적
Worker 수

고정 3명이 아니라 Mission Pack 독립성·충돌 위험·토큰 비용을 보고 Manager가 결정합니다.

중앙화
Git Integration

Worker끼리 merge하지 않습니다. Manager가 충돌 맵과 통합 순서를 관리합니다.

조기
Compile / Build

마지막 빌드에서 누락을 발견하지 않도록 Mission Pack과 Integration Wave마다 검증합니다.

실행
UX Verification

UI는 컴파일 성공으로 끝내지 않고 가능한 경우 실제 실행 화면과 UX Contract를 비교합니다.

2. 설치

ZIP을 프로젝트 저장소 루트에 풉니다.
기존 소스 폴더와 같은 레벨에 CLAUDE.md, AGENTS.md, .ai/가 있어야 합니다.
정책 파일을 먼저 Git에 commit합니다.
새 Worktree/Agent가 정책 파일을 상속하려면 정책 파일이 base commit에 존재하는 것이 중요합니다.
Claude Code 또는 Codex를 저장소 루트에서 시작합니다.
처음에는 평소처럼 자연어로 목표를 전달하면 됩니다.
중요: ZIP을 풀기만 하고 commit하지 않은 상태에서 병렬 Worktree를 먼저 만들면 새 Worktree가 정책 파일을 갖지 못할 수 있습니다. 정책 파일 commit → 개발 시작 순서를 지키십시오.

4. 토큰 로딩 전략

문서 전체를 모든 세션이 읽는 구조가 아닙니다. 메인 Manager만 필요한 핵심 문서를 읽고, Worker는 Manager가 만든 작은 Mission Packet만 받습니다.

7. Mission Pack과 Worker

Task 하나마다 Session을 만드는 방식은 피합니다. Manager는 context cohesion이 높은 Task를 하나의 Mission Pack으로 묶습니다.

MISSION: Camera Delete Core

GOAL
Non-main imported cameras must be reliably deletable.

OWNERSHIP
- CameraManager.*
- CameraItem.*

TASKS
1. Fix deletion guard.
2. Fix stale main-camera state.
3. Add regression coverage.

POLICY
- autonomous
- smallest safe diff
- Windows only
- no merge
- self-review/self-fix

VERIFY
- affected compile
- relevant tests
핵심: Worker 수는 3명으로 고정하지 않습니다. 일반적으로 1–6 범위에서 독립 Mission Pack, critical path, 충돌 위험, context bootstrap 비용을 보고 Manager가 결정합니다.

8. Git 충돌을 가장 먼저 줄이는 구조

이 시스템은 conflict 해결 능력보다 conflict 예방을 우선합니다.

  • 병렬 실행 전 파일·symbol 단위 Conflict Map 작성
  • 동일 write ownership 금지
  • shared header / hotspot 변경은 serialize 또는 한 Mission Pack으로 통합
  • Worker는 서로 merge하지 않음
  • Manager가 중앙 Integration Queue 관리
  • hotspot 작업은 오래 쌓지 않고 early integration
  • 반복 conflict는 PROJECT_LESSONS.md에 기록

10. 빌드 후 예상치 못한 모습 방지

의미 있는 UI 변경은 구현 전에 작은 UX Contract를 만듭니다.

ENTRY
Scene Graph context menu

ACTION
Delete

MAIN CAMERA
Delete disabled

TOOLTIP
Main Camera cannot be deleted.

SUCCESS
Camera disappears immediately.

ERROR
Reason is visibly explained.

그 후 가능하면 Build → Launch → 실제 화면/상태 확인 → UX Contract 비교까지 수행합니다. 컴파일과 테스트가 모두 PASS여도 실제 화면이 의도와 다르면 완료가 아닙니다.

12. 적대적 검증

Risk기본 전략
LOWSelf Review + deterministic check
MEDIUMCohesive batch 또는 fresh adversarial review
HIGH구현 전 challenge + 구현 후 fresh review. 가능하면 Claude ↔ Codex 교차 검증

반대 계열 agent를 직접 호출할 수 없는 환경이라면 fresh same-family reviewer로 대체하고 최종 보고서에 FALLBACK REVIEW로 명시합니다.

13. Manager 경험을 다음 프로젝트에 이식

Manager의 전체 대화 history를 복제하지 않습니다. MANAGER_PLAYBOOK.md에 일반화된 전략만 축적합니다.

Project A
  ↓
Telemetry / Lessons
  ↓
PROJECT_LESSONS.md
  ↓
Generalizable?
  ↓
MANAGER_PLAYBOOK.md (candidate)
  ↓
Comparable projects confirm
  ↓
verified
  ↓
Copy latest MANAGER_PLAYBOOK.md to Project B

한 프로젝트의 특수한 경로·workaround는 PROJECT_LESSONS.md에만 남깁니다. 이렇게 해야 Negative Transfer를 줄일 수 있습니다.

권장 운영: 여러 프로젝트를 시작할수록 최신 MANAGER_PLAYBOOK.md를 개인 템플릿 저장소에 반영해 새 프로젝트의 초기 전략 비용을 줄이십시오.

15. 첫 프로젝트 시작 방법

기존 프로젝트

1. ZIP을 repository root에 풉니다.
2. 정책 파일을 commit합니다.
3. Claude Code 또는 Codex를 엽니다.
4. 평소처럼 목표를 말합니다.

예:
"카메라 삭제 버그를 조사하고 수정해. UX와 회귀까지 확인해."

Manager는 PROJECT_CONTEXT.md가 비어 있으면 현재 작업에 필요한 범위에서만 repository를 조사하고 stable fact를 채우도록 지시되어 있습니다.

새 프로젝트

프로젝트 목적을 자연어로 전달하면 됩니다. 처음부터 모든 Architecture 문서를 직접 작성할 필요는 없습니다.

"이 저장소에서 새로운 Web/PWA 프로젝트를 시작한다.
목표는 ...
첫 usable version까지 자율적으로 개발해."
